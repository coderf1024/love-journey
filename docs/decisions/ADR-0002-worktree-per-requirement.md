# ADR-0002：一个需求一个 worktree + 分支

- 状态：已被 [ADR-0005](./ADR-0005-branch-only-workflow.md) 取代（2026-10-25）
- 日期：2026-10-25

> 本文仅作历史记录。现行规范为“一个需求一个分支，直接在主工作目录开发，不使用 worktree”。

## 背景

开发模式是一个人 + 一个 AI，但会同时推进多个需求，并在需求间来回切换。共用目录和分支容易把未完成的改动混在一起，AI 也容易丢失上下文。

## 决定

- 每个需求有一个任务 ID：`LJ-YYYYMMDD-NN-short-slug`。
- 每个需求一个 worktree + 一个功能分支：`feat/<task-id>`、`fix/<task-id>`、`chore/<task-id>`。
- 每个需求一个 `docs/work/<task-id>/` 文件夹，至少包含：
  - `brief.md` 需求与验收标准
  - `plan.md` 方案与任务拆分
  - `STATUS.md` 当前状态、分支、已完成、下一步
  - `QA.md` 验收记录
  - `notes.md` 决策、发现、遗留
- `docs/work/BOARD.md` 维护所有进行中需求。
- 切换需求前，必须先更新当前任务的 `STATUS.md` 并提交/记录当前进度。

## 取舍

- 优点：需求互不污染；AI 可以在新会话快速恢复上下文；出问题可单独回滚。
- 代价：worktree 目录多，需要记得切换；需要维护文档。
- 不选择：全部在 main 上开发，或者只靠聊天记录交接。

## 影响

- 新任务从 `docs/work/_template/` 复制。
- 数据迁移、线上写操作不要同时跨两个任务执行。
- 当前工程规范基线 (`LJ-20261025-001`) 是在已有未提交功能分支上完成的；从下一个需求开始严格使用独立 worktree。
