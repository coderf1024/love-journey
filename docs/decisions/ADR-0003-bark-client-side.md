# ADR-0003：Bark 客户端发送，无 cron，模板可配置

- 状态：已采纳
- 日期：2026-10-25

## 背景

这个网页不是常驻应用，没有后端。用户和管理员都需要在关键事件发生时收到站外通知。引入完整推送服务或定时扫描的成本高于收益。

## 决定

- 使用 Bark，管理端配置用户/管理员两把 key。
- 事件在动作发生的页面里直接调用 Bark `POST /push`，不新增定时任务。
- 每个事件有发送开关，默认开启。
- 每个事件有 title/subtitle/body/url 模板，变量在发送时替换。
- 用户通知默认带 `{userOrderUrl}` 深链，打开小灶页并选中对应饭点。
- 没有站内消息中心；“需要你处理”只承载页面内可操作事项。

## 取舍

- 优点：零后端、低成本、通知内容可配置、能跳回具体订单饭点。
- 代价：用户/管理员不打开页面就不会产生对应事件；页面关闭期间没有补发；Bark key 在 OSS 文档里可读。
- 不选择：Actions 定时扫描、Web Push、自建通知服务。

## 影响

- 新增通知事件时先加 event、模板、开关和变量，再接入触发点。
- 不要把 Bark key 打印或写进前端代码。
- 模板是用户可编辑的，不要假设固定文案；默认模板集中在 `BARK_TEMPLATE_DEFAULTS`。
