# ADR-0004：不新增构建/测试工具链，手动验收

- 状态：已采纳
- 日期：2026-10-25

## 背景

项目是静态 vanilla JS，没有 package.json、构建步骤或测试套件。一个人 + AI 的开发模式下，引入 Playwright/lint/打包器会增加维护成本和上下文负担。当前需求主要是 UI 和轻量数据操作，人工验收可以直接覆盖。

## 决定

- 保持零构建：线上产物就是仓库文件。
- 不新增 dev-only package.json、Playwright、lint 或测试框架。
- 质量闸门使用：
  - `node --check` 检查 JS 语法；
  - 浏览器手动检查 320/390/1280；
  - 关键路径手动验收（登录、下单、出餐、发卡、Bark）；
  - 任务 `QA.md` 逐项勾选。
- 未来如果需求复杂到手动验收不可靠，再单独开 ADR 评估工具链，不在日常任务里顺手引入。

## 取舍

- 优点：部署简单、没有额外依赖、AI 只需理解一套源文件。
- 代价：没有自动化回归保护；重复 UI 检查耗时；容易漏边界情况。
- 不选择：当前引入完整测试框架。

## 影响

- 每个任务必须在 `QA.md` 写清手动验证步骤和结果。
- 不把临时 Puppeteer 脚本、node_modules 或测试依赖提交进仓库。
- 修复 bug 时优先补一条可复现的手动验收步骤。
