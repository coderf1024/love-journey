# ADR-0005：只建分支，不使用 worktree

- 状态：已采纳
- 日期：2026-10-25
- 任务：工程规范调整（无独立任务 ID）

## 背景

ADR-0002 要求每个需求一个 worktree。实际使用下来，worktree 的隔离收益有限：这是一个人 + 一个 AI 的项目，同一时间基本只推进一个需求；而每次都要多记一个目录、多维护一份预览服务和缓存版本，合并后还要清理 worktree，步骤反而变多。

真正需要保留的是**分支隔离**：不同需求的提交不要混在一起，验收和回滚仍然按分支进行。

## 决定

- 一个需求一个分支：`feat/<task-id>`、`fix/<task-id>`、`chore/<task-id>`，从当前工作分支拉出。
- 直接在主工作目录切换分支开发，**不再创建 git worktree**。
- 任务文档、`STATUS.md`、`BOARD.md`、QA 和验收流程保持不变。
- 切分支前必须提交当前改动；一个分支同一时间只承载一个需求。
- 合并回基线分支用 `git merge --no-ff`；`main` 仍然只在人工验收后合并。

## 取舍

- 优点：目录唯一，预览服务、字体和缓存版本只维护一份；操作步骤更少。
- 代价：不能同时在两个需求上并行修改文件；切换需求前必须提交。
- 不选择：继续使用 worktree（ADR-0002）；或者直接在 `main` 上开发。

## 影响

- [ADR-0002](./ADR-0002-worktree-per-requirement.md) 被本 ADR 取代。
- `CLAUDE.md`、[需求流程](../work/README.md)、[发布手册](../runbooks/release.md) 同步更新。
- 历史任务文档里的 worktree 记录保留为历史，不再作为操作规范。
