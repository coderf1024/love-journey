随机按钮样式 · 三案（待选）

高保真，同尺寸对比

三个方案都是 26×26 的纯图标按钮，位置相同（菜单标题行右侧、计数左边），只有外形和配色不同。点击后都打开同一个礼盒弹窗。

A · 描边方钮 当前实现

菜单 28 道

方角 + 1px 灰描边 + 玫红图标。安静，和「28 道」同高，不抢菜单标题。
缺点：单独看像系统图标，不太像「可以点一下的玩法」。

B · 浅粉实心圆钮 更像玩法

菜单 28 道

圆角、浅粉底、玫红描边、玫红图标。比 A 更像「可点击的小机关」，又不至于太重。
缺点：和「＋我想吃」的虚线粉框略近。

C · 深墨实心圆钮 最显眼

菜单 28 道

同尺寸、深墨实心、米白图标，和「去确认」按钮同一套墨色。最容易被发现。
缺点：在纸色页面上略重，可能抢「菜单」标题。

C · 深墨圆钮

尺统一规格

26×26，图标 14px，位置和间距三案完全一致，所以换案只改底色/描边/圆角三项。

动按下反馈

三案都用同一个反馈：按下缩放 0.94；A 变浅粉底，B/C 变深一档。抽奖中禁用时统一 40% 透明。

选我的看法

A 最安静但不明显像玩法；B 平衡最好；C 最显眼但和页面墨色块（去确认）会有一点争抢。倾向 B。

05

规则与边界

随机只负责缩小范围

价钱与数量

  • 固定 20 币，下单扣，取消整单全退。
  • 一单最多一道；可与普通菜同单，也可单独成单。
  • 点 ＋ 直接加购，不弹说明，和普通菜一致。

遮揭晓

  • cooking 之前只显示「你做的我都爱吃」，之后显示菜名 + 「大厨做的」。
  • 订单卡、订单详情、空间订单列表同一套判断。
  • 不额外推送，复用现有 cooking 通知。

随随机

  • 池子 = 全部在售菜（打开弹窗时读取当前菜单，不按分类）。
  • 一次只出一道；「再抽一次」重放动画，排除上一道。
  • 抽中不自动加购；加购是用户点的这一下。
  • 下架菜不进池子；池子为空时按钮禁用。

动动画

  • 礼盒抖 2 次（约 1.1s）→ 盒盖飞走 → 12 颗碎屑炸开 → 结果卡升起。
  • prefers-reduced-motion 下跳过动画，直接出结果。
  • 纯 CSS + 少量 JS，无第三方动画库。

图照片

  • 置顶卡用海报图（OCR 文字在图里），缩略图按方图裁切。
  • 出餐照照常拍；这一道（含手写）的出餐照只写订单 servedImage，不进菜品图集。

不不做

  • 库存 / 食材管理；摇一摇；第三方库。
  • 新增 Bark 事件、应用内消息中心、盲盒分类。
  • 多道空位、事后差价结算。
