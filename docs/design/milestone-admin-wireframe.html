图片上传与兜底

上传复用菜品图的压缩流程（最长边 1600px、JPEG 0.82），写入 uploads/milestones/。封面按 4:3 居中裁切，卡片和详情共用。图片加载失败时只隐藏图片，下面的渐变和年份还在，不会出现破图图标。

旧数据提醒：线上有 13 条回忆带旧 image 字段但当前不展示；实现后会自动恢复显示，需要逐条打开检查图片是否还有效。

数据与写入

只写 content/milestones.json 一份文档，条数有界，整份读、整份写。保存时补 updatedAt，新记录生成 ms_<时间戳>，旧记录沿用已有 ms_001 形式 id。

  • 新增、编辑、删除都走同一个保存函数。
  • 日期留空 → 归入「旧时光」，仍可编辑。
  • 删除是硬删除；封面文件保留。
  • 不做拖拽排序，展示顺序只由日期决定。

本次不做

  • 多图相册 / 详情图集
  • 拖拽排序、置顶
  • 回收站、草稿、定时发布
  • 用户端提交或编辑回忆
  • Bark 通知、导出/导入

需要你确认

  1. 封面比例：固定 4:3（和现有卡片、详情一致），上传后居中裁切。是否接受？如果希望保留原图比例，卡片会出现留白或裁切不一致。
  2. 单图还是多图：原型按「一条回忆一张封面图」设计。如果详情需要多张照片轮播，需要额外加 images[] 和详情图集，工作量会增加。
  3. 删除策略：硬删除 + 二次确认，不做回收站。是否可接受？
  4. 入口位置：移动端放「系统 → 数据」，桌面端同时在侧栏「系统」组增加入口。是否合适，还是希望放到「经营」组？
  5. 旧图处理：恢复展示后，13 条旧 image 会自动出现；是否需要在管理端加「图片失效」提示或批量清理入口？
