B · 数据流与触发

1
管理端保存

写入 OSS space.settings.morningGreeting：{ enabled, recipients: ["user", "admin"] }。与现有 Bark 配置同一份文档，不新增文件。

2
Cloudflare Cron 触发

Cron 表达式 14 0 * * *（UTC），即北京时间每天 08:14。时间固定在 Cloudflare，管理端只显示、不能改。

3
Worker 执行

匿名读取 OSS 的 space.json（公开读，无需密钥）→ 若 enabled 为真，拉天气与一句话，计算恋爱天数，按 recipients 逐个调用 Bark /push。Bark 密钥由 OSS 读取，不进 Worker 环境变量。

4
发送标记与补发

每次发送成功后写 OSS greeting/2026-11-12.json，只存日期、发送时间、状态和收件人结果，不存天气和一句话。管理端首页只用它判断今天是否已发。补发在浏览器里现取天气（open-meteo）和一句话（shadiao）后直接发，发完更新发送状态为 resent（部分失败则为 partial）。

5
与 push.py 的对应

天气 weather_res、恋爱天数 get_love_day()（起点 2020-12-20）、一句话 get_word()（长度 ≤ 20 字，循环取）逐项移植；微信模板消息换成 Bark 三段式。

已确认 1：收件人

长期设置用两把现有 Bark 密钥（用户 / 大厨）各勾选。「发送测试」单独再选一次收件人，只影响这一次。

已确认 2：文案映射

先按 push.py 映射，发出来后再调。天气失败的兜底文案暂不处理。

已确认 3：补发在管理端直接发

不做 Worker 的 HTTP 入口。管理端直接调 Bark 补发。

已确认 3-1：天气源换成 open-meteo

原天气接口 t.weather.itboy.net 无跨域头且是 http，浏览器取不到，弃用。新源 open-meteo（open-meteo.com）返回 Access-Control-Allow-Origin: *，免 key，本机请求可用（存在代理假 IP，国内无代理直连待验证），返回 WMO 天气码和当天最高最低温，需要在前端映射成中文（例如 45 → 雾）。补发和 08:14 Worker 用同一个源，不再需要快照。

已确认 3-2：补发不经过 Worker

天气和一句话都在浏览器里现取，补发直接调 Bark，不做 Worker 入口，也不写当天内容快照。

待你确认 4：Worker 写 OSS 的凭证

「今天已发」标记需要写 OSS，Worker 要带 AccessKey。已确认放在 Cloudflare Secret；用户追加决定复用站点现有 Key，已完成配置。原 RAM 权限保持不变，实际权限并不只限于早安目录。

已确认 5：分支

不建新分支，直接在当前 worktree 分支 work/261112-daily-job 上开发。CLAUDE.md 同步更新。

已确认 6：部署工具链

可以引入 wrangler。CLAUDE.md 的「不引入构建工具链」需要改成「需要时经 ADR 批准」，并开新 ADR 取代 ADR-0003 的「无 cron」。
