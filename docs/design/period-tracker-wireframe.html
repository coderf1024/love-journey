生理期 · 原型 v2

一期只做四件事：记录、预测、美柚数据导入、每日提醒。照顾清单、厨房联动、一键求助、回顾都放在二期（原型里只留一个入口占位，不展开）。

判断标准只有一条：记录不能比美柚慢，预测不能比美柚差，而且必须能解释自己。所以原型里刻意保留了「依据」「自检」「数据不够」这些平时会被产品砍掉的东西——它们是「不输」的证明，不是装饰。

05 · 预测什么时候算、算多远 WHEN & HOW FAR

唯一的触发点 数据变了才重算

1
数据变了 → 立刻重算
记录开始 / 结束 / 补记 / 删除 / 导入完成 / 「这次不准」。写成功后当场算，结果写回文档。除此之外没有第二个触发点。
✕
预测日过了 → 不重算
预测日过了她还没记录，分不清是预测算错还是她没记。这时候重算，等于用「没记」去改预测——但没记不等于没来，算出来只会越偏。
✕
Worker 不做任何补算
Worker 每天 09:00 只读缓存判断要不要推送，不重算、不写 periods.json。它是个纯只读的闹钟，出错的面小得多。

过期了改状态，不改数字。预测原样留着，界面从「还有 5 天」变成「已过 3 天」，区间照旧显示，加一句「如果已经来了，记一下为准」。
为什么这是对的：预测的价值是「当时这么说」，不是「现在永远对」。原样留着才能事后回测「它到底准不准」；每次都重算，回测对标的是一个一直在动的目标，等于没法验证。
缓存 + asOf：界面上写「预测于 11.07 生成」，比一个永远在变的数字可信。

决定结论对原型的影响
首页入口 方案 A（独立细条），按需出现 只在「距下次 ≤ 7 天」或「经期中」显示；其余时间首页完全不提，入口留在「空间 → 生理期」。阈值在管理端可改。

预测的展示粒度 不给单日，区间不超过 3 天 周期不规律那屏从「5–14 天」改成固定 3 天窗口（11.13 – 11.15）+ 明确指出可能提前或推迟。代价：窗口收窄 → 回测命中率会下降，这个数字要如实展示，不粉饰。
保存后的反馈 弹窗，不是页内横幅 弹窗里 4 件事：记了什么 / 和预测差多少 / 下次变成什么 / 撤销 + 知道了。记录是低频重要动作，值得一次明确收尾。
日历视图 必须有，作为生理期页默认视图 新增第 04 节：月历 + 已记录实心 / 预测虚线圈 / 导入金色小点；点日期弹底部操作。分段控件切「日历 / 预测 / 记录」。
过期后的补录提醒 过期第 3 / 5 / 7 / 10 天各推一次，之后停 只提醒记录，不重算预测。固定 4 次，不每小时骚扰也不无限期；期间一旦记录即停止后续推送。
排卵日 / 排卵期 日历上显示，对齐美柚 排卵日 = 下次预计开始日 − 14 天，排卵期 = 前 5 到后 1 天（共 7 天）；青色与经期粉色区分。默认开启，可在管理端或当天卡片里关。口径是「推算值 · 参考值」：不写受孕概率、不叫安全期、明说不能作为避孕或备孕依据。
预测的触发与范围 只有数据变更才重算；预测过期不重算（改状态）；Worker 只读不补算。一次只预测下一个周期 新增第 05 节：唯一触发点 + 两个被否掉的触发点；过期后卡片褪色显示「已过 N 天」、区间原样保留；日历只画一段虚线；四条不预测的边界。

结束记录 不自动结束 超过 10 天只提示一次，给「补结束日 / 拆开 / 删除」三个动作，系统不改数据；进行中的记录不参与周期样本，避免把预测带歪。
