+ 新功能公告

一次上线解决两件事：让「谢谢大厨」有看得见的回馈，也让以后每次新功能都有固定的告知入口。 返币是这次公告的第一条内容，所以两个功能放在同一个任务里。下面先确认交互，确认后再改页面代码。

定稿 返币时机 出餐后即可返 沿用现有「谢谢大厨」入口，一单一次；不要求先点「吃好啦」。
定稿 返币金额 默认 10 币 space.settings.thanksReward 可改，设为 0 即关闭；首版不做管理端 UI。
定稿 公告触达 首次弹窗 + 空间回看 只弹最新一条；之后从「空间 → 更新公告」进入历史列表。
定稿 公告发布 默认草稿 · 独立发布 新建只能存草稿；发布 / 下线 / 重新发布都在列表上单独操作。代码先上线并 smoke，公告后发布。

B4 触达规则 state flow

ANNOUNCEMENT FLOW

什么时候弹，什么时候不弹

① 管理端先存草稿 公告写入 content/announcements.json，新建状态固定为 draft；编辑器里没有状态选项。
② 列表上单独发布 只有 status === 'published' 的公告下发给用户；发布时按时间生成 14 位版本号（如 20261103120210），按 publishedAt 倒序，只弹最新一条。
③ 查本机已读 localStorage 里按 dbRoot() 隔离，存已读公告 id 数组。
④ 未读 → 弹窗 关闭 / 知道啦 / 去看看都写入已读；下次不再自动弹，但空间入口仍可回看。
不会弹的情况 已读 / 公告不是 published / 当前有其他 sheet 或确认框 / 公告读取失败。读取失败不阻塞页面，只在空间入口显示「暂时读不到更新」。

不写 OSS：已读是设备本地状态，不增加写请求，也不影响测试库 / 线上库的数据。

04

规则与边界

实现时按这几条落地；有冲突以这里为准，再回写 brief / plan。

返返币规则

  • served / completed 且未感谢时可点，一单一次。
  • 按钮文案保持「谢谢大厨」；返币只在 toast 和流水里体现。
  • 流水类型 = 「谢谢大厨 + 哪一餐」，例如「谢谢大厨 10.24 周六 午餐」。
  • 金额读 space.settings.thanksReward，缺省 10；0 表示关闭。
  • 钱包流水 id 固定为 thanks_<orderId>，写入前先查重；失败回滚感谢。

告公告规则

  • 只展示 status === 'published' 的公告，按 publishedAt 倒序。
  • 版本号不手填：发布时由 publishedAt 生成 YYYYMMDDHHmmss（如 20261103120210），精确到秒。
  • 新建固定 draft；只能在列表上发布，不能跳过草稿直接发布。
  • draft → published → offline → published，其余流转一律拒绝。
  • 已发布必须先下线才能删除；下线不删数据。
  • 条目是纯文本，不配图标；CTA 文案和跳转地址必须成对填写。
  • 已读存 localStorage，key 带 dbRoot()；进入空间列表即标已读。

边失败与边界

  • 公告读取失败不阻塞页面；空间入口显示「暂时读不到更新」。
  • 公告为空时隐藏空间入口，不显示空列表。
  • 弹窗出现前检查是否已有 sheet / 确认框打开。
  • 感谢按钮点击后立即禁用，防连续点击。
  • 公告文本只做纯文本渲染；CTA 链接只允许站内 index.html#… 或 https 外链。
  • CTA 只填文案或只填地址时，保存直接报错，不发草稿。

ORDER上线和公告的先后顺序

  1. 先合并代码：推送 main，bump 缓存 token（如 20261103-01），等 EdgeOne / GitHub Pages 部署完成。
  2. 线上 smoke：确认新功能真的可用（返币、公告弹窗、空间入口）。
  3. 再建公告草稿：管理端新建公告，填标题 / 条目 / CTA，保存草稿。
  4. 最后发布：确认代码已上线后，在列表点「发布」。用户下次打开才会看到弹窗。
首次上线特别说明：公告 UI 本身要靠这次代码上线，所以第一次必须先部署代码，再发布公告。以后公告 UI 已在线，草稿可以提前写，但仍然等代码上线后再点发布。

本轮已按反馈定稿

  1. 返币时机：出餐后即可，一单一次。
  2. 金额：默认 10，space.settings.thanksReward 可改，首版不做 UI。
  3. 公告触达：首次弹窗 + 空间入口；不做首页 banner、不做 Bark。
  4. 已读范围：只在本设备，换手机 / 清缓存会再弹一次。
  5. 按钮文案：保持「谢谢大厨」，返币只在 toast 和流水里体现。
  6. 公告状态：新建只能存草稿，列表上单独发布；严格按草稿 → 已发布 → 已下线 → 重新发布流转。
  7. 公告条目：不要图标，纯文本一行一条；CTA 文案和跳转地址必须成对。
  8. 版本号：不手填，发布时按时间自动生成 14 位数字（如 20261103120210）。
  9. 发布顺序：代码先上线并 smoke，再发布公告；首次上线也要先部署公告 UI。
