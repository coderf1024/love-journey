# 术语表

## 产品与角色

| 名称 | 定义 |
|---|---|
| 恋爱空间 | 整个产品的称呼。一个空间固定两个成员：用户和大厨/管理员。 |
| 用户端 | `index.html`，用户预约、点菜、看订单、使用恋爱卡的一侧。 |
| 管理端 | `admin.html`，管理员/大厨操作的一侧。**不要叫「大厨端」**。 |
| 大厨 | 空间里的管理员角色，也是做饭的人。可以说「大厨接单」「大厨发币」，但后台系统叫「管理端」。 |
| 小灶 | 用户端的周末点餐/预约页面，底部 tab 名称；不是管理端的小灶 tab。管理端的订单区在「订单」。 |

## 用户端导航（位置不变，名称已更新）

| tab 名称 | `data-page` / 页面 id | 页面职责 |
|---|---|---|
| **我们** | `home` / `#page-home` | 首页、相爱时间、里程碑、地图、手帐内容 |
| **小灶** | `order` / `#page-order` | 周末饭点、点菜、订单进度、确认下单 |
| **恋爱卡** | `coupons` / `#page-coupons` | 恋爱卡列表、筛选、二维码 |
| **空间** | `me` / `#page-me` | 个人/空间页：余额、订单、恋爱币、恋爱卡流水 |

> 旧文档里的「首页」现在叫「我们」；旧文档里的「我们页面」现在叫「空间」。内部 id 仍然是 `home` / `me`，不要因为改名去改路由。

## 管理端导航

- 移动端：首页 / 订单 / 恋爱卡 / 系统
- Web：经营（首页 / 订单 / 恋爱卡 / 恋爱币）、系统（系统设置 / 菜单 / 空间资料）
- 「首页」在管理端仍然叫首页，不要和用户端的「我们」混用。

## 订单与饭点

| 名称 | 定义 |
|---|---|
| 饭点 / slot | 周六/周日的 12:00 或 20:00，带一个 `slotKey`，例如 `20261024-1200`。 |
| 预约 | 用户提前选择饭点并下单。 |
| 订单状态 | `pending 待接单 → accepted 已接单 → prepping 备菜中 → cooking 制作中 → served 已出餐 → completed 已完成`，另有 `cancelled 已取消`。 |
| 出餐 | 状态变成 `served`。管理端必须先为这一单的每道菜拍照并上传成品图。 |
| 完成 | 状态变成 `completed`；用户端按钮是「吃好啦」。 |

## 菜品图片

| 名称 | 定义 |
|---|---|
| 主图 `image` | 菜品封面，菜单卡使用它；`images[0]` 与它保持一致。 |
| 图片集 `images[]` | 有序图片数组，第一张是主图，后续包含历次出餐成品图。 |
| 本次出餐图 `servedImage` | 订单项上的快照，指向这一单出餐时拍的那张成品图。它不等于菜品主图。 |
| 历史订单展示 | 订单项先展示菜品主图；「本次出餐」区域单独用大图展示 `servedImage`。 |

## 其他

| 名称 | 定义 |
|---|---|
| 恋爱卡 | 可核销的卡券，周更 Action 自动发放，也可管理端手动补发。 |
| 恋爱币 | 用户钱包余额；管理端发币，下单扣币，取消退款，可设置透支上限。 |
| 文档存储 | OSS bucket 下的 JSON 文档库；没有传统数据库和后端。 |
| 缓存版本 | URL 上的 `?v=YYYYMMDD-N`，每次改 JS/CSS/字体/音频都要 bump。 |
| Bark | 站外通知通道；用户/管理员各一把 key，模板和发送时机可配置。 |
