## 背景与目标

现有 Bark 默认模板是「系统日志 + 状态机事件名」的写法：副标题写 `管理端` / `用户端`，正文以内部订单号开头，标题是 `新预约` / `开始制作` / `用户取消` 这类枚举值，收件人读起来像开发者通知。

目标是把五个事件按收件人拆成两套口吻：

- 大厨侧（`newOrder` / `userCancel` / `nudge`）：系统通知，事件名 + 人 + 菜 + 金额 + 要做什么，可扫读，无 emoji、无订单号。
- 用户侧（`cooking` / `served`）：男朋友发来的消息，第一人称「我」、第二人称「你」，说在做什么、还要多久、点开看什么，不出现金额和状态枚举。

## 范围

- 要做：
  - 重写 `js/store.js` 的 `BARK_TEMPLATE_DEFAULTS` 五条默认模板。
  - 新增派生变量 `{userLabel}`、`{noteBlock}`、`{reasonBlock}`，避免空备注/空原因留下悬空前缀。
  - 出餐通知把第一张 `servedImage` 作为 Bark `image` 配图。
  - 管理端模板变量面板补充新变量。
  - `docs/runbooks/bark.md` 写入两套口吻规则。
  - 缓存 token 升级。
- 不做（非目标）：
  - 不改事件开关、密钥、Bark 发送时机。
  - 不改通知分组 `group`。
  - 不改线上 OSS 里可能已保存的模板（需要人工在管理端重新保存或清空）。
  - 不修 `{minutes}` 的「距下单时间」语义，默认模板暂不使用它。

## 验收标准

1. 管理端模板弹窗的样例预览中，五条模板分别呈现系统通知 / 男友口吻两种语气。
2. 备注为空时 `newOrder` 不出现「备注：」空行；取消原因为空时 `userCancel` 不出现「原因：」空行。
3. 出餐通知请求体包含 `image`（第一张成品图）。
4. 用户侧模板不出现订单号、金额、状态枚举；大厨侧不出现「管理端 / 用户端」。
5. `node --check js/store.js` 通过，页面 console 无报错。

## 涉及面

- 页面：`admin.html` 模板编辑器；用户端和管理端通知展示（Bark App）。
- 数据/OSS：`space.settings.bark.templates` 的保存值优先级高于默认值。
- 通知/Bark：五个事件模板、出餐配图。
- 管理端：变量面板新增三项。
- 兼容/迁移：旧模板若已保存仍按旧文案发送，需要人工处理。
