# LJ-20261025-004-admin-confirm-layer · 实现方案

## 总体思路

确认框是“弹窗之上的弹窗”，层级必须高于 `.admin-modal`；键盘关闭顺序也必须按视觉层级从高到低处理。

## 改动清单

| 文件/模块 | 改动 |
|---|---|
| `admin.html` | `.admin-dialog` 的 `z-index` 从 `100` 改为 `140`。 |
| `admin.html` | Escape 处理改为先判断 `admin-confirm`，再判断图片灯箱、出餐弹窗、模板弹窗、菜品弹窗。 |

## 数据结构 / 兼容 / 迁移

- 纯 CSS/事件顺序调整，不涉及数据。
- `.admin-dialog` 的 140 高于 `.admin-modal`（110）和 `.image-lightbox`（130），确认框始终在最上层。

## 分步任务

- [x] 1. 提升确认框层级。
- [x] 2. 调整 Escape 关闭顺序。
- [x] 3. 无头浏览器验证层级和点击命中。

## 手动 QA 重点

- 模板弹窗 → 发送测试 → 确认框可点。
- 确认框打开时按 Escape 只关确认框。
- 取消订单、删除恋爱卡等原有确认框照常工作。

## 风险与回滚

- 风险低：仅层级和键盘事件顺序。
- 回滚：恢复 `z-index: 100` 和原 Escape 顺序。
