# LJ-20261026-001-bark-accept-icon · 接单通知与空间头像图标

- 状态：in-review
- 提出人：人
- 日期：2026-10-26
- 分支：`feat/LJ-20261026-001-bark-accept-icon`

## 背景与目标

1. 管理员点「接单」时，用户端目前收不到任何通知；需要在 pending → accepted 时给用户发一条消息。
2. Bark 通知目前显示默认图标；需要用空间头像作为所有通知的自定义图标。

## 范围

- 要做：
  - 新增 `accepted` Bark 事件：管理员接单时推给用户，使用男友口吻。
  - 管理端通知设置增加「接单」开关和模板入口。
  - `sendBark()` 所有推送附带 `icon` = 空间头像（绝对地址；SVG/空头像不传）。
  - 同步 Bark 手册、架构流程、CLAUDE.md、CHANGELOG、缓存版本和字体。
- 不做（非目标）：
  - 不改其他事件的口吻和默认文案。
  - 不改通知分组、发送时机和密钥逻辑。
  - 不处理用户端头像圆角/裁切，Bark 自行显示。

## 验收标准

1. 管理员点「接单」后，用户手机收到「接单啦，这顿我来做 ❤️」。
2. 管理端「系统 → 通知」出现「接单」行，可开关、可编辑模板、可发送测试。
3. 所有测试推送和真实推送的请求体都包含 `icon`，值为空间头像 URL。
4. 未设置头像或头像为 SVG 时不传 `icon`，推送照常发送。
5. 原有五个事件行为不变。

## 涉及面

- 页面：`admin.html` 系统通知设置。
- 数据/OSS：读取 `space.avatar`；不写数据。
- 通知/Bark：新增 `accepted` 事件，所有事件新增 `icon`。
- 兼容/迁移：线上 `space.settings.bark.events` 没有 `accepted` 时默认开启；保存一次通知设置后会写入。
