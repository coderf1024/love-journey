# LJ-20261026-001-bark-accept-icon · 笔记

## 决策

- 2026-10-26：`accepted` 归入用户侧口吻，和大厨侧系统通知分开。
- 2026-10-26：图标在 `sendBark()` 统一注入，不在各调用点传参，避免漏掉某个事件。
- 2026-10-26：头像为空或 SVG 时不传 `icon`；Bark 图标需要位图 URL。

## 发现

- 线上空间头像是 OSS 的 HTTPS 绝对地址，Bark 可以直接拉取。
- `space.settings.bark.events` 里没有 `accepted` 时按默认开启处理；只有保存过一次通知设置后才会写入该 key。

## 遗留风险 / 后续任务

- 如果以后头像改成本地 SVG 或相对路径，图标会自动省略；需要位图上传。
- Bark 自定义图标需要 iOS 15+。
