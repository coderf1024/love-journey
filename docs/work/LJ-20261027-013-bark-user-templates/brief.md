# LJ-20261027-013 · 用户侧 Bark 模板精简并改为正式口吻

- 状态：in-progress
- 提出人：人
- 日期：2026-10-27
- 分支：`fix/LJ-20261027-013-bark-user-templates`

## 背景与目标

用户侧的接单 / 开始制作 / 出餐三条 Bark 通知正文偏长（每条两行，含有「等我一会儿」「点开看看」等口语），在锁屏上会占三到四行。
人选择的方向：保留菜名、副标题继续用 `{slot}`，标题和正文比现在更正式一些。

## 范围

- 要做：
  - 调整 `BARK_TEMPLATE_DEFAULTS` 的 `accepted` / `cooking` / `served` 三条用户侧模板：标题去掉「啦」等口语助词，正文压到一行并保留 `{items}`、`{etaMinutes}`。
  - 升级缓存 token，让已打开的页面拿到新脚本。
- 不做（非目标）：
  - 不改管理端四条系统通知（新单 / 取消 / 催一催 / 菜品申请）。
  - 不改 Bark 发送逻辑、事件开关、模板变量。
  - 不改已保存到 `space.settings.bark.templates` 的线上覆盖值；需要人在管理端「恢复默认」后保存（见 STATUS）。

## 验收标准

1. 接单通知：标题 `这单我接下了 ❤️`，副标题为饭点，正文 `记下了:{items}，到点我叫你`（一行）。
2. 开始制作通知：标题 `开始下厨了 🔥`，正文 `正在做 {items}，大约 {etaMinutes} 分钟`。
3. 出餐通知：标题 `饭菜做好了 ❤️`，正文 `{items} 刚出锅，趁热吃 · 照片点开看看`，仍附带第一张成品图。
4. 管理端「通知设置」模板编辑器里这三条显示新文案，「恢复默认」取到新值。
5. 缓存 token 已升级，刷新后 `store.js` 为新版本。

## 涉及面

- 页面：`index.html`、`admin.html`、`use.html`（缓存 token）
- 数据/OSS：无写入
- 通知/Bark：仅用户侧三条默认模板
- 管理端：模板编辑器的默认值与预览
- 兼容/迁移：线上若已保存过用户侧模板，需要在管理端逐条「恢复默认」并保存

## 风险与开放问题

- [ ] 线上 `space.settings.bark.templates` 是否已保存过用户侧模板未知（本地无 OSS 凭证）；若无保存则默认值直接生效。
