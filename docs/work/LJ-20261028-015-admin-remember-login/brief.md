# LJ-20261028-015 · 管理端关闭浏览器后免重新登录

- 状态：in-review
- 提出人：人
- 日期：2026-10-28
- 分支：`261028_space_fix`（按人指定的分支名，从 `main` 拉出）

## 背景与目标

管理端登录态存在 `sessionStorage`（`admin.html` 的 `lj-admin-session`），生命周期跟着标签页/浏览器窗口，关掉浏览器就清空，每次都要重新输入口令。

目标：改成 `localStorage` + **7 天滑动过期**。只要 7 天内打开过一次管理端，就不需要重新登录；超过 7 天没打开才要求重新输入口令。

## 范围

- 要做：
  - 登录态存储从 `sessionStorage` 换成 `localStorage`；
  - 有效期内每次成功加载管理端数据都重置计时（滑动续期）；
  - 过期时顺手清掉过期记录；
  - 恢复登录失败时不再清掉登录态（只提示刷新重试）。
- 不做（非目标）：
  - 不做「记住我」勾选框（方案 B，无新增 UI）；
  - 不做签名/加密 token（`CryptoUtils` 可逆、密钥在前端包里，没有实际安全收益）；
  - 不做服务端会话/可撤销 token（项目无后端）；
  - 不改口令校验逻辑。

## 验收标准

1. 输入口令登录后关闭浏览器，重新打开 `admin.html` 直接进入管理端，不需要再输口令。
2. 在有效期内每次打开都会续期；人为把记录改成 8 天前，重新打开要求登录，且过期记录被清除。
3. 点「退出登录」后重新打开 `admin.html` 要求登录。
4. 管理端其他功能（订单、菜单、恋爱卡/币、系统设置）不受影响，console 无报错。
5. 用户端 `index.html`、核销页 `use.html` 无变化。

## 涉及面

- 页面：`admin.html`（内联脚本，三处）
- 数据/OSS：无
- 通知/Bark：无
- 管理端：仅登录态
- 兼容/迁移：旧的 `sessionStorage` 记录会随窗口关闭自然消失，无需迁移；老用户首次需重新登录一次。

## 风险与开放问题

- [x] 公用设备风险：管理端本来就只给两个人用，口令和 AccessKey 都在前端包里，登录门是形式性的，长期记住不额外降低安全性。
- [ ] iOS Safari / 微信内置浏览器可能因长期不访问或系统回收清掉 `localStorage`（约 7 天无交互），属于浏览器行为，代码无法绕过；加到主屏当 PWA 更稳。
- [ ] 无痕/隐私窗口关闭后必清，属于浏览器行为。
