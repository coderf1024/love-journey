# LJ-20261029-004 · 管理端里程碑配置（含图片）

- 提出人：人
- 日期：2026-10-29
- 分支：`feat/LJ-20261029-004-milestone-admin`（本需求后续改动都在这条分支上，不再新建分支）

## 背景与目标

「岁月留痕」的 41 条回忆目前只存在 OSS 的 `content/milestones.json`，管理端没有任何维护入口。011 因为「没有图片来源」，把回忆卡片和详情封面的图片展示去掉了，统一改成 v0–v3 纯色渐变。

人确认：本需求**只改管理端**，用户端代码和渲染保持不变。管理端补上里程碑配置：新增、编辑、删除回忆，并为每条回忆上传/替换封面图；图片只保存在数据里，用户端仍显示纯色封面，等以后单独做用户端展示。

## 范围

- 要做：
  - 管理端「系统 → 数据」新增「岁月留痕」入口，进入独立列表视图。
  - 列表按年份分组、日期倒序；支持搜索标题/描述，按「全部 / 有封面 / 无封面」筛选。
  - 新增/编辑弹窗：日期、标题、描述、封面图（上传或粘贴 URL）。
  - 删除回忆，使用管理端现有的自定义确认框。
  - 封面图上传到 OSS `uploads/milestones/`，客户端压缩（与菜品图一致）。
  - 管理端列表显示封面缩略图；没有封面的回忆显示渐变占位。
  - 管理端编辑弹窗内预览 4:3 封面图。
- 不做（非目标）：
  - 不做多图相册；一条回忆只有一张封面图。
  - 不做手动拖拽排序；展示顺序仍由日期决定（011 的规则不变）。
  - **不改用户端**：不恢复 `index.html` / `js/app.js` / `css/style.css` 的图片渲染，用户端仍显示纯色封面。
  - 不做用户端提交/编辑回忆。
  - 不做回收站、草稿、定时发布。
  - 不改 Bark、订单、钱包、恋爱卡。
  - 不改 `content/milestones.json` 的既有数据，除非人在管理端主动保存。

## 验收标准

1. 管理端「系统」页出现「岁月留痕」入口，显示总条数和有封面条数。
2. 列表按日期倒序、年份分组，无日期条目归入「旧时光」并排最后。
3. 支持按标题/描述搜索，以及「全部 / 有封面 / 无封面」筛选。
4. 新增一条回忆后，管理端列表按日期归位；数据写入 `content/milestones.json`。
5. 编辑标题/日期/描述/封面图后，管理端列表立即更新。
6. 上传/替换封面图后，管理端缩略图和预览显示新图；图片写入 `uploads/milestones/`。
7. 删除一条回忆需要二次确认，删除后管理端列表移除。
8. 没有封面的老回忆在管理端显示渐变占位，不出现破图。
9. 用户端 `index.html`、`js/app.js`、`css/style.css` 没有改动，回忆仍显示纯色封面。
10. 320 / 390 / 1280 下管理端列表和弹窗正常，console 无报错。
