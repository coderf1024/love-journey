## 背景与目标

「岁月留痕」的 41 条回忆目前只存在 OSS 的 `content/milestones.json`，管理端没有任何维护入口。011 因为「没有图片来源」，把回忆卡片和详情封面的图片展示去掉了，统一改成 v0–v3 纯色渐变。

现在需要在管理端补上里程碑配置：新增、编辑、删除回忆，并为每条回忆上传/替换封面图。用户端恢复图片展示；没有图片的老回忆继续用纯色渐变兜底，不出现空白或破图。

## 范围

- 要做：
  - 管理端「系统 → 数据」新增「岁月留痕」入口，进入独立列表视图。
  - 列表按年份分组、日期倒序；支持搜索标题/描述，按「全部 / 有封面 / 无封面」筛选。
  - 新增/编辑弹窗：日期、标题、描述、封面图（上传或粘贴 URL）。
  - 删除回忆，使用管理端现有的自定义确认框。
  - 封面图上传到 OSS `uploads/milestones/`，客户端压缩（与菜品图一致）。
  - 用户端「我们」页回忆卡片、「全部回忆」时间线、回忆详情恢复封面图展示。
  - 没有 `image` 或图片加载失败时，回退到现有纯色渐变封面。
- 不做（非目标）：
  - 不做多图相册；一条回忆只有一张封面图。
  - 不做手动拖拽排序；展示顺序仍由日期决定（011 的规则不变）。
  - 不做用户端提交/编辑回忆。
  - 不做回收站、草稿、定时发布。
  - 不改 Bark、订单、钱包、恋爱卡。
  - 不改 `content/milestones.json` 的既有数据，除非人在管理端主动保存。

## 验收标准

1. 管理端「系统」页出现「岁月留痕」入口，显示总条数和有封面条数。
2. 列表按日期倒序、年份分组，无日期条目归入「旧时光」并排最后。
3. 新增一条回忆后，用户端刷新即可看到，位置按日期排序正确。
4. 编辑标题/日期/描述/封面图后，管理端列表和用户端卡片、详情同步更新。
5. 上传封面后，用户端卡片和详情显示照片；照片上仍能看清时间信息。
6. 删除一条回忆需要二次确认，删除后用户端不再出现。
7. 没有封面的老回忆仍显示原来的纯色渐变，不出现破图。
8. 320 / 390 / 1280 下管理端列表和弹窗正常，console 无报错。
