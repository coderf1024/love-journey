# LJ-20261030-001 · 首页加载速度优化

- 状态：in-progress
- 提出人：人
- 日期：2026-10-30
- 分支：直接在当前分支开发（人要求，不开新分支）

## 背景与目标

首页首屏慢，人可感知的三个位置：

1. 字体：两个 woff2 合计约 965KB，首屏文字出现后还会二次换字体。
2. 天数：`#days` 先显示 0，等 9 个 OSS 文档全部读完才渲染。
3. 地图：ECharts 1.02MB + 地图 JSON 582KB，首页加载阶段就触发。

目标：重复访问首屏立即有内容；首次访问减少字节和往返；地图延后且数据变小；不改变视觉与交互。

## 范围

- 要做：
  - 字体按实际使用位置重新子集化（`--font-cute` / `--font-display`）。
  - OSS 读请求改为普通 `fetch`（去掉每个文档的 CORS 预检）。
  - OSS SDK 从首屏移除，写入时按需加载。
  - 首屏缓存优先（localStorage，stale-while-revalidate）。
  - 天数使用本地兜底起始日，不等网络。
  - 地图 JSON 简化、加版本号、延后初始化。
  - 未访问 tab / 全部回忆弹层延迟渲染；修掉轮播的强制同步布局；页面隐藏时暂停倒计时。
  - 三个页面加 bucket `preconnect`，缓存 token bump。
- 不做（非目标，人已确认）：
  - P2：不用静态 SVG 替换 ECharts，不做 Service Worker，不做兜底字体 unicode-range。
  - 不动地图涟漪动画（常驻，保持原样）。
  - 不改数据模型、不改 OSS 写入路径的语义。

## 验收标准

1. 本地 8888 用低速 4G + 4× CPU 打开：`#days` 在首屏 200ms 内出现（有缓存时 0 网络等待）。
2. Network 面板中 OSS 文档请求不再出现 OPTIONS 预检。
3. 首页首屏不再加载 aliyun-oss-sdk；字体合计传输明显下降；地图在数据渲染之后才请求。
4. 320 / 390 / 1280 三档视觉、地图交互、涟漪效果与改动前一致。
5. 写操作（下单、发卡、出餐、删除）仍正常，SDK 按需加载成功。

## 涉及面

- 页面：index.html / admin.html / use.html
- 数据/OSS：js/oss-utils.js、js/store.js
- 管理端：仅按需加载 SDK 与缓存 token
- 兼容/迁移：无需迁移；缓存 key 带 `dbRoot()`，测试库/线上库隔离

## 风险与开放问题

- [ ] bucket 为公共读，读接口从 SDK 改为匿名 fetch；若 bucket 策略变化，读会失败。
- [ ] 字体子集若漏字，会回退到宋体；按实际字体位置取字降低风险，改内容后仍需重跑脚本。
- [ ] localStorage 缓存可能短暂显示旧数据；后台刷新后自动校正。
