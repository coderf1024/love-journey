# LJ-20261102-001 · 谢谢大厨返币 + 新功能公告

- 状态：draft（方案已按人反馈修订，待复核）
- 提出人：人
- 日期：2026-11-02
- 分支：`feat/thank-chef-10-coins-announcement`（已存在）

## 背景与目标

「谢谢大厨」现在只写一条感谢语，用户点完没有任何可见反馈，缺少动力；同时每次上线新功能，用户端没有一个稳定的告知入口，只能靠人主动说。

这次一起做两件互相配套的事：

1. **谢谢大厨返 10 恋爱币**：让感谢有实际回馈，也鼓励用户用完餐后回来点一下。
2. **新功能公告**：管理端发布更新说明，用户端首次打开自动弹一次，之后可以在「空间 → 更新公告」回看。

两件事属于同一次上线，而且公告的第一条内容就是「谢谢大厨返币」，所以合为一个任务和一个分支。

## 范围

### 要做

- `thankChef()` 首次成功时给用户返 10 恋爱币，每单只返一次；钱包流水新增 `thanks` 类型。
- **按钮文案不变**：仍然只写「谢谢大厨」；不在按钮上体现返币，用户订单卡也不额外加奖励标记。
- 返币反馈放在 toast：`已谢谢大厨，+10 恋爱币`。
- 钱包流水类型 = 「谢谢大厨 + 哪一餐」，例如 `谢谢大厨 10.24 周六 午餐`。
- 管理端订单卡显示用户感谢语和「已返 10 币」。
- 新增 `content/announcements.json` 文档和读写 API。
- 公告状态使用 `draft / published / offline`，严格流转：
  - 新建公告**只能保存为草稿**，编辑器里没有状态选项。
  - 草稿在列表上单独「发布」后才能变成已发布。
  - 已发布只能「下线」；下线后才能「重新发布」或删除。
  - 不允许从草稿直接跳过发布，也不允许删除已发布公告。
- 管理端「系统 → 更新公告」：公告列表、新增 / 编辑、发布 / 下线 / 重新发布、删除。
- 公告条目**不带图标**：纯文本一行一条，用户端统一用圆点。
- **版本号不手填**：发布时按 `publishedAt` 自动生成 `YYYYMMDDHHmmss`（精确到秒，如 `20261103120210`）；草稿显示「未发布」。
- **发布顺序**：先上线代码并线上 smoke，再发布公告；首次上线时公告 UI 本身也依赖这次部署。
- CTA 必须成对配置：`文案 + 跳转地址`；站内用 `index.html#order` 这类地址，也支持 https 外链。
- 用户端：首次打开弹公告；「空间 → 更新公告」入口、未读红点、历史公告列表。
- 已读状态存 `localStorage`（按 `dbRoot()` 隔离），不写 OSS。

### 不做（非目标）

- 不做公告定时发布、富文本 / Markdown、图片附件。
- 不做公告条目图标选择器；首版直接不要图标。
- 不做公告的 Bark 推送；首版靠站内弹窗。
- 不做返币金额的管理端 UI；首版默认 10，可用 `space.settings.thanksReward` 覆盖，设为 0 即关闭。
- 不补发历史订单的感谢返币。
- 不做多设备已读同步。
- 不做首页常驻公告 banner（首版只在首次打开弹窗 + 空间入口）。

## 验收标准

1. 出餐后按钮仍显示「谢谢大厨」；点击后 toast 显示 `已谢谢大厨，+10 恋爱币`，订单卡不出现额外奖励标记，按钮变「已谢谢大厨」。
2. 同一单重复点击、刷新、重新进入，都不会重复返币；钱包只有一条 `thanks` 流水。
3. 空间 → 恋爱币流水出现 `谢谢大厨 10.24 周六 午餐` `+10`，类型文案和图标与发币、点餐、退款可区分。
4. 管理端订单卡显示用户感谢语和「已返 10 币」。
5. 新建公告保存后状态是「草稿」，编辑器里没有状态字段；草稿只能在列表上点「发布」。
6. 已发布只能「下线」；已下线只能「重新发布」或「删除」；已发布不能直接删除；所有非法流转被拒绝。
7. 用户端（清掉已读或换设备）首次打开弹最新已发布公告；点「知道啦」「去看看」或关闭后不再自动弹。
8. 空间出现「更新公告」入口和未读红点；进入列表能看到历史公告，进入后红点消失。
9. 公告条目无图标；CTA 文案和跳转地址缺一不可，缺少时保存报错；内部地址能跳到对应 tab。
10. 新建公告不填版本号；发布后版本显示发布时间的 14 位数字（`YYYYMMDDHHmmss`，如 `20261103120210`）；草稿显示「未发布」。
11. 按发布顺序执行：代码上线 + 线上 smoke 后，公告才发布；首次上线先部署公告 UI。
12. 320 / 390 / 1280 无横向溢出，console 无报错，三页缓存版本已 bump。

## 涉及面

- 页面：`index.html` + `js/app.js` + `css/style.css`；`admin.html`；`use.html` 只 bump 版本。
- 数据 / OSS：`commerce/wallet.json` 新增流水类型；订单 `thanks` 增加 `reward` / `rewardTxId`；新增 `content/announcements.json`。
- 通知 / Bark：首版不新增事件；管理端订单卡展示感谢。
- 管理端：系统新增公告管理视图 / 编辑器，状态动作与编辑表单分离。
- 兼容 / 迁移：旧订单无 `reward` 不发币；公告文档不存在时按空列表处理；无需迁移脚本。

## 已确认的决定

- 返币时机：出餐后即可，一单一次。
- 返币金额：默认 10，`space.settings.thanksReward` 可改，首版不做 UI。
- 公告触达：首次弹窗 + 空间入口；不做首页 banner、不做 Bark。
- 已读范围：只在本设备，换手机 / 清缓存会再弹一次。
- 按钮文案：保持「谢谢大厨」，返币只在 toast 和流水里体现。
- 公告状态：新建只能存草稿，列表上单独发布；严格按草稿 → 已发布 → 已下线 → 重新发布流转。
- 公告条目：不要图标，纯文本一行一条；CTA 文案和跳转地址必须成对。
- 版本号：不手填，发布时按时间自动生成 `YYYYMMDDHHmmss`（精确到秒，如 `20261103120210`）。
- 发布顺序：代码先上线并 smoke，公告后发布；首次上线先部署公告 UI。
