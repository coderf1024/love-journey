# LJ-20261102-001 · 笔记

## 决策

- 2026-11-02：返币和公告合为一个任务 / 分支。原因：公告的第一条内容就是返币功能，两者同一次上线；拆开会导致同一次发布跨两个分支。
- 2026-11-02：返币在 `thankChef()` 里完成，而不是新增独立按钮。复用现有入口，用户不需要理解「感谢」和「领币」两步。
- 2026-11-02：钱包流水 id 用 `thanks_<orderId>`。比随机 id 多一层幂等保护，能挡住「钱包写成功、订单写失败」后的重试。
- 2026-11-02：公告单独放 `content/announcements.json`，不放 `space.settings`。避免和 Bark / 空间资料保存产生读改写竞争，也方便以后做公告列表。
- 2026-11-02：已读状态只存 `localStorage`，key 带 `dbRoot()`。不写 OSS，不新增服务端状态。
- 2026-11-02：首版不做公告的 Bark 推送。站内弹窗已经覆盖「打开就能看到」，Bark 留作后续。
- 2026-11-02：公告首版只渲染纯文本字段，不支持 HTML / Markdown，避免 XSS 和样式失控。
- 2026-11-03：按钮文案保持「谢谢大厨」，不在按钮或订单卡上体现返币；奖励只在 toast 和钱包流水里出现。原因：人要求入口维持原样，避免把「感谢」做成促销按钮。
- 2026-11-03：钱包流水类型 = 「谢谢大厨 + 哪一餐」，例如「谢谢大厨 10.24 周六 午餐」；不单独造「返币 / 奖励」类型。
- 2026-11-03：公告状态改为 `draft / published / offline`，编辑器不提供状态字段。新建固定草稿；发布 / 下线 / 重新发布都在列表上单独操作，严格按 `draft → published → offline → published` 流转。
- 2026-11-03：已发布公告不能直接删除，必须先下线；草稿和已下线可以删除。
- 2026-11-03：公告条目不要图标，纯文本一行一条；用户端统一圆点。原因：管理员无法稳定输入合适图标，且字体子集 / 平台 emoji 表现不一致。
- 2026-11-03：CTA 改为 `{ label, href }` 成对配置；站内地址统一成 `index.html#<page>`，外部只允许 https。只填一项时保存报错。
- 2026-11-03：版本号取消手填，改为发布时按 `publishedAt` 自动生成 14 位数字 `YYYYMMDDHHmmss`（精确到秒，如 `20261103120210`）。原因：人要求精确到秒，方便和部署时间 / 日志对照；排序仍只看 `publishedAt`。
- 2026-11-03：不单独存代码版本 / `releaseRef`。版本号本身足够精确，直接作为发布标识；不再维护第二套版本字段。
- 2026-11-03：发布顺序定为「代码先上线并 smoke → 建公告草稿 → 发布公告」。首次上线时公告 UI 依赖这次代码部署，不能先发公告。
- 2026-11-03：公告读取改为 `dbGet(..., { fresh: true })`（cache-buster + `no-store`）。OSS 不返回 `Cache-Control`，浏览器可能在写入后仍从启发式缓存读到旧文档；实测立即「保存草稿 → 发布」会报找不到公告，加 fresh 后通过。`loadAnnouncementsDocForAction()` 保留 600ms 重试作为兜底。
- 2026-11-03：管理端公告动作直接用 store 返回值更新 `adminData.announcements` 并重绘，不再在动作后立刻回读整份文档，避免读后写竞态。

## 发现

- `thankChef()` 目前只读订单，不读 `space` / 钱包；加返币后需要同时读订单、钱包和空间设置，注意失败顺序。
- 钱包流水渲染在 `walletEntryHTML()` 里有固定标签表 `{ grant, order, refund }`，新增 `thanks` 要同时补图标和标签。
- 管理端订单卡在 `orderCard()` 附近用 `extras.push('用户说：...')` 展示感谢，返币标记可以并到同一行。
- 空间页面已经有 `state.meView` 子页面机制，公告列表直接加一个 `announcements` 视图即可，不需要新 sheet。
- 首页 `loadAppData()` 是 9 个并行读；公告不要塞进这 9 个，改为数据渲染完成后再读。
- 管理端现有编辑弹窗是「表单 + 底部按钮」结构；公告状态动作要拆到列表卡片上，编辑器只保留「保存草稿 / 保存修改」。

## 遗留风险 / 后续任务

- 订单 + 钱包的非原子写仍未彻底解决；确定性 tx id 只覆盖部分失败场景。
- 多设备已读不同步；如果以后需要，得引入服务端已读或 `space` 上的成员已读记录。
- 公告目前没有定时发布；如果要做「周五晚上自动上线」，需要新增 `publishAt` 和前端过滤逻辑。
- 返币金额没有管理端 UI；改金额要手动改 `space.json`。
- 公告状态动作是读改写；两个管理端标签页同时操作可能丢失一次状态推进，首版接受。
- CTA 链接白名单只允许站内 hash 和 https；以后如果要跳 `use.html?id=...`，需要扩展校验规则。
