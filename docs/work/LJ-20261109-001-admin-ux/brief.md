## 背景与目标

管理端已经承载了订单、恋爱卡/币、菜单、岁月留痕、公告、通知配置，但日常使用里有几处卡点：找不到用户端入口、首页待办漏状态、系统页又长又混、输入框字号突兀、回忆编辑在手机上难用、订单看不了详情、菜品标签不够用。

目标：在不改数据结构和部署方式的前提下，把管理端的高频路径理顺。

## 范围（人已确认）

1. **首页打开用户端**：只在首页顶部右侧放「用户端 ↗」；快捷操作保持 3 格。地址优先 `space.settings.links.user`；本地测试库用相对 `index.html` + 当前 `?env`。
2. **需要你处理口径**：待接单 / 备菜中 / 制作中 / 已出餐 + 超时订单 + 待审核菜品申请；**已接单只在饭点当天出现**；已完成、已取消不出现。
3. **系统只做导航**：Bark 抽成二级页「通知」；系统一级页只留导航行 + 摘要；桌面侧栏同步。
4. **输入字号**：视觉全局 14px，并且不能出现「iOS 聚焦放大、收键盘不回缩」。原因：iOS 在计算字号 <16px 时自动放大约 1.14 倍；直接写 14px 会触发。方案见 D 段，**待人从 A/B/C 中选定**。
5. **新增回忆**：**保留 4:3 大图**（宽度限到 `min(100%, 266px)`，约 200px 高）；日期改整行日期按钮 + 自绘日历弹层；年份变成日期下方说明；删除降级为底部文字链接。
6. **订单详情**：二级页（`adminView = order-detail`）；卡片整卡可点；详情含菜品、出餐快照、备注、支付、催单、状态时间线、操作条。
7. **菜品标签**：3 → **8 个**：下饭 / 香辣 / 酸甜 / 咸鲜 / 拿手菜 / 酱香 / 暖胃 / 红烧；**每个菜最多选 2 个**（和用户卡/详情显示数一致，不出现“选了不显示”）。酱香与红烧都保留。
8. **补充采纳**：系统导航行加处理角标；菜单按标签筛选。

补做（订单详情已确认，顺手做）：详情页内直接出餐 / 取消。

不做（非目标）：

- 不改 OSS 文档结构，不加索引字段，不迁移数据（标签只做白名单扩展）。
- 不引入后端、不加定时任务、不加账号体系。
- 不做系统三级菜单。
- 不新增构建/测试工具链。
- 暂不做：催单/超时置顶（除非复核时要求）、桌面页头用户端入口、订单列表缩略图、待办超过 6 条折叠。

## 验收标准

1. 首页顶部能一键打开用户端；本地测试库打开 `index.html` + 当前 `?env`，线上打开 `space.settings.links.user`。
2. 待接单 / 备菜中 / 制作中 / 已出餐 / 待审核菜品申请出现在「需要你处理」；已接单**只在饭点当天**出现；已完成、已取消不出现；主按钮跟随状态。
3. 系统一级页只剩导航行；通知二级页可编辑、保存、测试；保存逻辑和生效行为不变。
4. 管理端输入框视觉明显小于现状；iOS 真机聚焦不放大页面，键盘收起后布局不跳，双指捏合不缩放。
5. 390 宽下新增回忆：封面仍是 4:3 大图，标题和描述可见；日期可点开日历选择，且为必填。
6. 管理端订单卡片可点开二级详情；详情操作可用，出餐仍走拍照弹窗；返回回到来源页。
7. 标签扩到 8 个后，旧菜品保存不被清空标签；用户端卡片仍只显示前 2 个；菜单可按标签筛选。
8. 系统导航行显示待审核数量角标。

## 涉及面

- 页面：`admin.html`；用户端 `js/app.js`（谢谢大厨 = 完成）、`js/store.js`（标签白名单）。
- 数据/OSS：只读写既有字段；`space.settings.links`、`space.settings.bark` 结构不变。
- 通知/Bark：模板、事件、发送时机不变，只改管理端 UI 位置。
- 兼容/迁移：无需迁移；标签白名单扩展后旧值保留。
