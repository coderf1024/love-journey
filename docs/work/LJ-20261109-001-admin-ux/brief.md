## 背景与目标

管理端已经承载了订单、恋爱卡/币、菜单、岁月留痕、公告、通知配置，但日常使用里有几处卡点：找不到用户端入口、首页待办漏状态、系统页又长又混、输入框字号突兀、回忆编辑在手机上难用、订单看不了详情、菜品标签不够用。

目标：在不改数据结构和部署方式的前提下，把管理端的高频路径理顺。

## 范围

要做（对应人的 7 条）：

1. 首页增加「用户端」快捷入口（顶部 + 快捷操作格）。
2. 「需要你处理」口径改为「所有未完成订单」+ 待审核菜品申请。
3. 系统一级页只做导航；Bark 抽成二级页「通知」；桌面侧栏同步。
4. 管理端输入框字号收紧（移动端 16px → 14px，聚焦临时 16px）。
5. 新增/编辑回忆的移动端布局重排；日期改成整行日期按钮 + 自绘日历弹层。
6. 订单可点开详情（二级页），含菜品、出餐图、备注、支付、状态时间线、操作。
7. 菜品标签从 3 个扩展到一组候选（新增项待人选）。

补充建议（原型 G 段，可做可不做）：

- 详情页内直接出餐 / 取消；
- 催单、超时订单在待办里置顶标红；
- 系统导航行加处理角标；
- 菜单按标签筛选；
- 桌面页头放「打开用户端」；
- 订单列表加菜品缩略图。

不做（非目标）：

- 不改 OSS 文档结构，不加索引字段，不迁移数据（标签只做白名单扩展）。
- 不引入后端、不加定时任务、不加账号体系。
- 不做系统三级菜单。
- 不新增构建/测试工具链。

## 验收标准

1. 首页顶部和快捷操作都能一键打开用户端；本地测试库打开的是 `index.html` + 当前 `?env`，线上打开 `space.settings.links.user`。
2. 待接单 / 已接单 / 备菜中 / 制作中 / 已出餐 / 待审核菜品申请都出现在「需要你处理」；已完成、已取消不出现；主按钮跟随状态。
3. 系统一级页只剩导航行；Bark 全部配置在「通知」二级页，保存逻辑和生效行为不变。
4. 移动端输入框视觉字号小于当前，聚焦不触发 iOS 自动放大；桌面端字号不变。
5. 新增回忆在 390 宽下一屏能看到封面缩略图、日期、标题、描述；日期可点开日历选择，可清空；空日期仍归入「旧时光」。
6. 管理端订单卡片可点开详情；详情里的操作按钮可用，出餐仍走拍照弹窗；返回能回到来源页。
7. 菜品标签候选扩展后，旧菜品保存不被清空标签；用户端卡片仍只显示前 2 个。

## 涉及面

- 页面：`admin.html`；用户端只有「谢谢大厨 = 完成」一项会动 `js/app.js`（**待确认**）。
- 数据/OSS：只读写既有字段；`space.settings.links`、`space.settings.bark` 结构不变。
- 通知/Bark：模板、事件、发送时机不变，只改管理端 UI 位置。
- 管理端：导航结构、首页待办、订单详情、回忆编辑弹窗、菜品标签。
- 兼容/迁移：无需迁移；标签白名单扩展后旧值保留。
