# LJ-20261112-001 · 每日早安问候（08:14 Bark）

- 状态：accepted（用户批准发布，自动早安保持关闭）
- 提出人：人
- 日期：2026-11-12
- 分支：work/261112-daily-job（当前 worktree 分支，不新建分支）
- 原型：[docs/design/morning-greeting-wireframe.html](../../design/morning-greeting-wireframe.html)

## 背景与目标

每天北京时间 08:14 给两个人各发一条 Bark 早安，内容沿用 push.py 的模板字段：标题带恋爱天数，副标题是日期和天气，正文是一句话。

现有 Bark 设计（ADR-0003）只在动作页面里发推送，没有定时任务，因此早安无法实现。本任务引入 Cloudflare Cron 触发的 Worker，并把开关、收件人和补发都放在管理端「系统 → 通知」里，配置持久化到 OSS。

## 范围

- 要做：
  - 管理端「通知」页新增「早安问候」分组：发送早安开关、收件人勾选（用户 / 大厨，至少一个）、发送失败告警开关、首页待办提醒开关、补发今天、发送测试（临时选收件人，只发一次，发前确认）。
  - Cloudflare Cron（`14 0 * * *` UTC，即北京 08:14）触发的 Worker：读取 OSS 的空间配置和恋爱开始日期，取天气（open-meteo）和一句话（api.shadiao.pro），按收件人推送 Bark，写发送记录。
  - 发送失败当场用管理员密钥推「早安发送失败」。
  - 管理端首页：08:30 后打开，若当天无已发送记录，「需要你处理」出现「今天早安未发出」（或「部分未送达」），右侧「补发」按钮。
  - 补发在管理端浏览器里直接完成（现取天气与一句话，直接调 Bark，只发给当天未成功的收件人）。
  - 发送记录 `love-journey/db/greeting/<YYYY-MM-DD>.json`。
  - ADR-0007；运维手册；wrangler 工具链仅限 `workers/morning-greeting/`。
- 不做（非目标）：
  - 第二个定时任务监督早安任务。
  - Worker HTTP 补发入口。
  - 当天天气/一句话快照。
  - 外部心跳服务（方案 3，暂缓，记在项目记忆里）。
  - 管理端修改 Cron 时间（时间只能在 `wrangler.toml` 改）。
  - 给其他推送事件加定时任务。

## 验收标准

1. 管理端「通知」页能保存早安开关、收件人、两个告警开关；刷新后保持。
2. 发送测试能临时选收件人发一次，且不写发送记录；发送前有确认框。
3. 08:14 Worker 正常运行时，两位收件人收到标题、副标题、正文一致的早安；发送记录为 `sent`。
4. 任一收件人或一句话失败时，按开关向管理员告警；天气失败只省略天气，不影响早安发出。OSS 配置不可读或 Bark 本身故障时告警可能无法送达。
5. 08:30 后若当天无已发送记录，管理端首页出现待办；点击补发后待办消失，收到早安，记录变为 `resent`。
6. 关闭「发送早安」后，Worker 当天不发送，管理端首页不出现待办。
7. 320 / 390 / 1280 宽度下通知页和首页无横向溢出；console 无脚本异常（当天缺记录的预期 OSS 404 单独注明）。
8. Worker 的 OSS 密钥通过 Cloudflare Secret 注入（按用户追加决定复用站点 Key）；本次新增文件不含真实密钥。

## 涉及面

- 页面：admin.html（通知页、首页待办）
- 数据/OSS：`space.json` 的 `settings.morningGreeting`；`greeting/<日期>.json`（Worker 与管理端补发写入）；Worker 以 RAM 子账号读写 `love-journey/db/greeting/`（代码写入该前缀；按用户新决定复用站点 Key，实际权限仍与站点一致）
- 通知/Bark：Worker 与管理端都调用 Bark `POST /push`；早安与失败告警的图标沿用空间头像
- 管理端：通知页分组、首页待办、补发与测试确认框
- 兼容/迁移：未开启早安时行为与现在一致；无历史数据迁移。缓存版本 token 从 `20261109-01` 升到 `20261112-02`。

## 风险与开放问题

- Cron 可能有分钟级延迟；08:14 不保证准时到达。
- Worker 共享站点 RAM Key；其实际权限未隔离到 greeting 前缀，将来可替换专用 Key。
- open-meteo 与 api.shadiao.pro 为第三方服务，失败时由告警和补发兜底。
- Worker 已部署并配置 Secret；管理端发布和首次真实推送仍待验收，见 [运维手册](../../runbooks/morning-greeting.md)。
