## 抠图做法（可复现）

原素材 `assets/media/cat/0b7035a5fc9d5df21a03eb052ddeb76e.jpg`（896×594，RGB 白底 JPG，无 alpha）。原图的「抠图」其实是把猫贴在纯白底上再采样，所以边缘需要重新做：

1. **Apple Vision 前景分割**（macOS：`VNGenerateForegroundInstanceMaskRequest`）取实例蒙版，得到 896×594 的软边掩码。轮廓准确，但 alpha 近乎二值（31% 为 0、65% 为 255），直接放大有锯齿和白边。
2. **白底判定**：蒙版会向外多包 1–2px 的纯白像素。对「距白色最远的通道差 `d = (255 - C).max()`」做软化，`w = clamp((d - 0.008) / 0.055, 0, 1)`，只有明显有色的像素才允许不透明。
3. **腐蚀核心**：蒙版做 `MinFilter(5)` 得 core，core 内保持 Vision 的原值，core 外乘 `w`，再 `GaussianBlur(0.9)` 得到自然抗锯齿边缘。
4. **白底解混**：`F = (C - (1-a)·255) / a`，去掉边缘像素里混进的白；`a < 0.04` 的像素 RGB 置 0，避免放大后出现白色毛刺。
5. 输出 RGBA → 裁到不透明包围盒 → 缩到 640px 宽 → 透明底 WebP（`cwebp -q 92 -alpha_q 100 -m 6`）。

验证：分别合成到纯黑、奶油 `#fbf6ec`、青绿 `#2f9b98` 三种底色下放大 2 倍检查，无白边、无彩色描边；深色底上胡须细节保留。

## 抠图的上限（2026-11-13 追加）

原型里换成透明底后，用户反馈「没区别」。原因是**问题不在白底，在轮廓**：原素材已经是「猫贴在纯白底上」的成品，底边是一条硬切直线、左肩是方角；Vision 抠图只能去掉白色，改不了形状，放在近白色的纸上自然看不出变化。

要真正改观，只能让模型按真实猫体重新生成 → 转图生图，提示词见 `image-prompts.md`。

## 发现

- 用户端「空间」是 4 个固定子页（`orders` / `wallet` / `cards` / `announcements` + `order-detail`），`js/app.js:2984` 有一份白名单、`openMeView()` 又有一份；加 `pet` 要同时改这两处、`renderMePage` 的标题映射，并决定 `pet` 是否进 `me-fixed-view`（建议不进，时间线要跟页面一起滚）。
- 管理端子页由 `SUB_VIEWS` + `switchView` 白名单 + `VIEW_TITLES` + `renderChrome` 高亮四处共同决定；桌面侧栏在 `admin.html` 的 `@media (min-width: 900px)` 块里，加「六一」时只在系统组末尾插一行即可，不需要新 tab。
- 管理端没有原生 `<select>`，全部用 `.choice-row`，样式在 `admin.html:836` 附近。
- 首页计时卡 `.timer-card` 是 `position: static`，要做「猫趴卡片边缘」需加 `position: relative`，并让图片容器自己 `overflow: hidden`（裁掉身体下半截），卡片本身不能裁，否则猫的头部也会被切掉。
- 原素材本身底边就是硬切的块状轮廓（不是自然毛边），所以抠图结果在这个位置也保持直线；这是素材限制，不是抠图失误。
- 本机 headless Chrome 有 500px 的最小视口，320/390 验证要用 iframe 固定宽度；正文页面宽度实测 `scrollWidth === clientWidth`。
