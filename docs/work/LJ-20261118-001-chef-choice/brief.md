## 背景与目标

用户点菜时有选择困难；大厨手上有存量食材（往往不在菜单里），希望由他决定做什么，避免浪费。

两个互补的入口：

1. **你做的我都爱吃**（固定 20 币）：用户不选菜，大厨**开始制作时**填上；用户通过现有「开始下厨了」Bark 通知知道吃什么。
2. **随机选一道**（点按钮）：用户愿意挑但拿不定主意，从当前可见的菜单里随机抽一道，高亮给用户看，由用户自己加进购物车。**不做摇一摇**（平台限制太多，见 `notes.md`）。

## 范围

- 要做：
  - 用户端菜单置顶卡（含真实照片）；加入/取消；购物车、订单卡、订单详情、空间订单列表的占位与揭晓。
  - 菜单工具栏「随机选一道」按钮：从当前分类可见菜随机抽取 → 滚动 + 高亮 + toast；不自动加购。
  - 管理端「开始制作」门禁：有空位未填时先弹填菜面板；填完一次性完成写菜名 + 进入 cooking + 发通知。
  - 填菜支持从菜单选一道，或手写菜单里没有的菜；手写也可上传一张图（可选）。
  - 出餐照：置顶卡和手写菜都按普通菜一样拍照出餐，但照片只写订单项 `servedImage`，不进菜品 `images[]`。
  - 菜单页顶部设置卡（开关 + 固定价）。
- 不做（非目标）：
  - 不做库存/食材管理；不做机选随机替代大厨。
  - 不做摇一摇；不引入第三方库。
  - 不新增 Bark 事件、不做应用内消息中心、不加盲盒分类。
  - 不多道空位、不做事后差价结算。

## 验收标准

1. 菜单「全部 / 快手菜 / 硬核菜」下置顶卡都在第一位，且有照片；关闭开关后用户端不显示。
2. 同一单只能加一次置顶卡；可与普通菜同单，也可单独一单只有它。
3. 点 + 立即加入购物车，不弹说明；行为与普通菜一致。
4. 下单扣 20 币；取消按整单全额退回。
5. 「随机选一道」只在当前分类可见菜里抽；结果高亮 + 滚动到它；不自动加购；同一分类连续抽不会重复上一道；分类没有菜时按钮不可用。
6. `cooking` 之前，用户端订单卡、订单详情、空间订单列表都看不到真实菜名；之后显示并标「大厨做的」。
7. 未填空位时无法进入 `cooking`；填完立即进入，发出的 cooking 通知正文是真实菜名。
8. 手写菜（菜单里没有）也能出餐；出餐照只写订单项 `servedImage`，`menu.dishes[*].images` 不增加。
9. 320 / 390 / 1280 三档无横向溢出，console 干净。
