## 发现

- `setOrderStatus` 进入 `cooking` 时会重新读取订单再发通知，所以先写菜名、再改状态即可让 `{items}` 带上真实菜名，无需新事件。
- `serveOrder` 现在按 `item.dishId` 取照片键；手写空位没有 `dishId`，必须改成按订单项下标。
- 用户端判断是否揭晓只能看**订单状态**（`cooking` 之前遮住），不能看字段是否为空。
- 随机选一道不需要后端、不需要传感器，是纯前端逻辑；原摇一摇调研保留在下面备查。

## 随机选一道（替代摇一摇）

- 池子 = 当前分类下 `available !== false` 的菜；抽不到就提示「这个分类还没有菜」。
- 排除上一道，避免连抽两次一样；高亮 3 秒 + toast，不自动加购。
- 不做摇一摇：需要 HTTPS、iOS 需手势授权、微信 WebView 不可靠、局域网 http 收不到事件（详见下节）。

## 摇一摇调研（已决定不做，保留备查）

| 环境 | 能否摇 | 说明 |
|---|---|---|
| iPhone Safari（iOS 13+） | 可以，需授权 | `DeviceMotionEvent.requestPermission()` 必须由点击触发；需 HTTPS |
| iPhone 微信内置浏览器 | 不确定，多数不可靠 | 可能没有该方法或收不到事件 |
| Android Chrome / 微信 | 一般可以 | 无需授权，但同样要 HTTPS |
| 桌面 / 模拟器 | 不行 | 无加速度计 |
| 局域网 `http://192.168.x.x` | 不行 | 非安全上下文，事件被拦 |

阈值做法（如以后重启）：相邻采样差做高通，静止约 9.8，阈值 14，冷却 1.2 秒。
