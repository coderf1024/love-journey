## 决策

- 把「发动态面板 UI 优化」并入本任务同一分支：日期选择是本任务刚加、尚未提交的改动，UI 打磨属于同一次交付，拆分支会把未提交改动带过去。
- 用户端日期最终改为**自绘日历**（年份快捷行 + 月份切换 + 周一开头的 6 周网格），与管理端日历同款；打开方式是在发动态面板里点日期块，日历以第二层底部面板覆盖在发布面板上，选完即回写并关闭。
- 两端发动态日历的年份快捷行固定为 2026–2030；管理端共用同一个日历，但生日/到家日/岁月留痕通过 `calendarTarget.inputId` 判断后仍用宽年份范围，避免旧日期（如 2023 生日）选不到。
- 日期块用普通 `<button>` + 隐藏 input 保存值，不再依赖原生 `input[type=date]`，避免各端原生控件样式不一致。
- 两端字段顺序统一为 文字 → 日期 → 照片；日期为必填，编辑时保留原日期。
- 管理端沿用现有 `date-picker-button` + 日历弹窗，不再使用简化按钮。
