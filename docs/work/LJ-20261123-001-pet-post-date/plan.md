# 实现方案

日期必填，默认当天；编辑时保留原日期。保存时将所选日期与原有时间部分合成 createdAt，继续兼容现有展示、排序和历史数据；updatedAt 记录实际更新时间。日期在共享数据层校验。

## 发布面板 UI

- 用户端日期改为**自绘日历**，交互与管理端一致：年份快捷行、上月/下月切换、周一开头的 6 周日历、今天描边、选中实心；点日期即回写并关闭。不再使用原生 `<input type="date">`。
- 两端发动态日历的年份快捷行只保留 **2026–2030**（2026 已过/当前，往后到 2030），避免一长排年份把日历挤高；月份切换仍可到更早/更晚。管理端共享日历的生日、到家日、岁月留痕仍保留宽范围，方便回到旧日期。
- 日期块是普通按钮（图标 + `YYYY年M月D日` + 周几/今天/昨天 + 右侧箭头），点击打开日历底部面板；下方保留「今天 / 昨天」快捷。
- 面板标题三栏居中；字数移入输入框右下角；照片区增加 `n / 9` 计数。
- 管理端：`#pet-moment-date-button` 使用标准的 `.date-picker-button` 结构（图标块 + 主文案 + 提示 + 箭头），打开现有日历弹窗；补「今天 / 昨天」快捷按钮；照片网格从 4 列改为 3 列。
- 两端字段顺序统一为文字 → 日期 → 照片；日期图标统一为内联 SVG 日历。
- 只动 UI 与日期快捷写入，不改数据结构和排序规则。
