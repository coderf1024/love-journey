## 背景与目标

六一也需要记录体重。现在没有地方记，也没有地方回看趋势。

目标：管理端录入体重，用户端只读查看曲线和明细；入口留在「六一」这一页，不新开一级菜单。

## 范围

- 要做：
  - 用户端六一页资料卡下新增一条体重卡（最新体重 + 较上次变化）；点整行打开底部弹窗。后台没有任何记录时，这张卡不渲染，资料卡只剩三项统计。
  - 弹窗 tab 切换「曲线 / 列表」；曲线支持近 1 个月 / 近 3 个月 / 全部，列表按月倒序并显示相对上一条的增减。
  - 管理端「系统 → 六一」新增「体重」段：趋势概要、记一笔、明细列表、修改和删除（删除二次确认）。
  - 单位固定「斤」，1 位小数；一天一条，同日再次记录等同覆盖（实际约一周称一次）。增减颜色按上涨绿、下降红（猫不需要减肥）。
- 不做（非目标）：
  - 用户端录入、编辑、删除。
  - 目标体重、体重提醒、Bark 通知、动态联动。
  - 用户端显示记录人。
  - 多宠物、多成员、导出。

## 验收标准

1. 管理端记一笔（日期 + 体重，0.1 斤步进）后，用户端六一页资料卡下出现体重卡「8.4 斤」，点击打开弹窗。
2. 用户端弹窗两个 tab 可切换；曲线点与列表记录一致，范围切换按记录日期过滤；不显示记录人。
3. 同一天重复记录只保留一条（覆盖），列表数量不增加。
4. 管理端删除某条后，用户端曲线、列表、体重卡同步更新；后台一条记录都没有时，用户端不渲染体重卡（不显示 0 斤或空入口）。
5. 320 / 390 / 1280 不横向溢出；iOS 聚焦体重输入不放大页面；控制台无报错。

## 涉及面

- 页面：`js/app.js`（六一页入口与体重弹窗）、`css/style.css`、`admin.html`（六一页体重段与录入弹窗）。
- 数据/OSS：`content/pet.json` 新增 `weights[]`（`{ id, date, weight, createdAt }`），整份写入；用户页本来就读这份文档。
- 通知/Bark：无。
- 管理端：`admin.html` 六一子页内新增，不新增系统菜单行。
- 兼容/迁移：`weights` 缺失时按空数组处理；不迁移历史数据。
